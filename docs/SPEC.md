# 统一体验规范 v2（所有机器人都按这个来）

[English](SPEC.en.md)

目的：不管背后是 Claude、Gemini 还是别的模型，用户在 Telegram 里看到的菜单、按钮、提示长得一样，用起来一样。
**功能怎么实现各自因地制宜，长相和手感统一。** 

## 0. 语言

- 自带两种语言：**中文**和**英文**。其他语言不内置：让用户自己的 AI 读英文版文档，照着翻译、自己装一套。
- 菜单显示哪种语言，Telegram 看的是**手机 Telegram 的界面语言**，不是聊天用的语言。很多人聊天用中文，Telegram 界面却是英文。
- 所以分两种情况：
  - **自己用的机器人**（只给一个用户用）：用 chat 范围（`scope: {"type":"chat","chat_id":<用户id>}`）设菜单，**不带 `language_code`**，文字用用户聊天时用的语言。这样不管手机界面是什么语言，看到的都是他习惯的那套。
  - **公开给很多人用的机器人**：默认范围设两套。`language_code: "zh"` 是中文，不带 `language_code` 的是英文。
- chat 范围的菜单优先于默认范围的菜单。
- 回复：跟用户说话用的语言一致。下面的固定格式都有中英两版。

## 1. 菜单（setMyCommands）

顺序和文字固定，不加 emoji，不加括号说明。

| 顺序 | 命令 | 中文 | English | 必须？ |
|---|---|---|---|---|
| 1 | /desk | 远程接管云电脑 | Take over cloud desktop | 装了 TapDesk 就放 |
| 2 | /new | 开新对话 | New conversation | 能做就放 |
| 3 | /remind | 快捷设提醒 | Quick reminder | 能做就放 |
| 4 | /jobs | 管理定时任务 | Scheduled tasks | 能做就放 |
| 5 | /memory | 查看长期记忆 | Long-term memory | 能做就放 |
| 6 | /usage | 查额度 | Usage limits | 必须 |
| 7 | /model | 选模型 | Choose model | 必须 |
| 8 | /effort | 思考强度 | Thinking effort | 必须（后端没有这个概念就不放） |
| 9 | /status | 当前设置 | Current settings | 必须 |
| 10 | /screen | 云电脑截屏 | Cloud desktop screenshot | 有云电脑就放 |
| 最后 | /help | 帮助 | Help | 必须 |

- 做不到的功能**不放进菜单**。不要放一个点了只会说"不支持"的入口。
- 新增功能：先写进这张表，定好顺序和中英文字，再各自实现。
- 注意：有的 Telegram 中继/插件自己会拦截 /status、/help（比如 Claude Code 官方插件），要改成转给 AI 或由中继按下面的格式回复。

## 2. 选择按钮（/model、/effort 以及其他让用户选的场合）

- 一律用 **inline 按钮**，挂在消息下面。**不用**输入框下面那种 reply keyboard，它会占着输入框，还会反复弹出来。
- 标题：`选模型（现在：XXX）`、`选思考强度（现在：XXX）`。
- 当前项前面加 `✅ `。
- 模型按钮每行 2 个，按钮文字就是模型名。最后单独一行：`默认（跟随 <程序名>）`。
- 思考强度每行 1 个：`低 low` / `中 medium` / `高 high` / `很高 xhigh` / `最高 max`。最后单独一行：`默认（跟随模型）`。
- 选项只列这个机器人真的能用的。Claude 有 Opus，Gemini 没有，就各列各的。
- 点了以后：
  - 按钮上方会弹出一个小提示：`已切换：X`（通用按钮写 `已选择：X`）。
  - 原消息改成：
    - 模型：`模型已切换为：X` + 换行 + `（对话不变，下一条消息起生效）`
    - 思考强度：`思考强度已切换为：X` + 换行 + `（下一条消息起生效）`
    - 其他选择：原文 + 空一行 + `✅ 已选择：X`
- 用户不点也没关系，直接打字照样聊。

## 3. 固定格式的回复

**/status**
```
模型：XXX
思考强度：XXX
工具权限：全部自动允许 | 自动允许（有安全检查） | 只聊天，不执行命令
后台状态：空闲 | 后台处理中（排队 N 条）
运行中定时任务：N 个（时区：Asia/Singapore）
对话：<会话编号或"（新对话）">
```

**/usage**（显示剩余百分比，10 格进度条）
```
<程序名> 额度
5 小时剩余：▓▓▓▓▓▓▓▓▓░ 92%
   Refreshes in 3h 52m
本周剩余：▓▓▓▓▓▓▓▓▓▓ 99%
   Refreshes in 153h 16m
```

**/jobs**（没有任务时）
```
暂无定时任务或提醒（时区：Asia/Singapore）。

用法示例：
· /remind 20m 喝水
· /remind 18:30 开会
· 直接聊天告诉我，比如「每天早上 8 点给我发科技早报」
```
有任务时，每条一行，后面跟「暂停/启用」「🗑 删除」按钮。

**/memory**
```
长期记忆

· <一条记忆>
· ...
```

**/help**
```
<程序名> 24 小时助手
直接发文字、图片、语音、视频或文件：接着当前对话处理
/desk 远程接管云电脑（用完自动关端口）
/new 开一个新对话
/remind 设快捷提醒（如 /remind 20m 喝水）
/jobs 查看和管理定时任务与提醒
/memory 查看长期记忆
/usage 查额度
/model 选模型
/effort 思考强度
/status 当前设置
/help 帮助
```
（只列菜单里真有的命令。）

**/screen**：默认截**机器人自己的云电脑桌面**（就是 /desk 接管的那个），直接发图。用户要看别的电脑（比如家里电脑）时，再按用户说的去截，不作为默认。

**/desk**：运行 `tapdesk/card.py "用户主动打开云电脑"`，发一张"🖥 电脑 · 需要操作"卡片：截图加「🖥 接管」按钮。详见 tapdesk/README.md。

## 3.5 电脑归属和共用

- **每个机器人默认操作自己的电脑**（自己的云电脑）。/desk、/screen 都是指自己那台。
- 操作别人的电脑（用户家里电脑、另一个机器人的服务器）**不放进菜单**，只有用户在聊天里明确要求时才做。
- **每个机器人都要有 /desk 和 /screen**，不能因为"电脑被别人占着"就不加。
- 几个机器人在同一台服务器上、共用一台云电脑时，用 `tapdesk/deskctl.sh` 这把"占用锁"排队：
  - 开始操作桌面或浏览器前：`deskctl.sh acquire <自己的名字> "<在做什么>"`。
  - 返回 BUSY（别人在用）时，给用户发一条带按钮的消息：
    ```
    云电脑现在正被 <对方> 用来：<在做什么>（已 N 分钟）
    [让它继续（默认）] [挤下它，我来用]
    ```
    - 用户不点：默认让它继续。你就等它用完（隔几分钟再 acquire），或者先做不需要桌面的部分。
    - 用户点"挤下它"：`deskctl.sh preempt <自己> "<在做什么>"`。
  - 操作中每一步之间：`deskctl.sh beat <自己>`。返回 PREEMPTED 就立刻停手，告诉用户"电脑被 X 拿去用了，我先停下"，等空了再继续。
  - 用完：`deskctl.sh release <自己>`。
  - 用户点「🖥 接管」时，TapDesk 会以 user 身份挤下所有机器人；用户点"我完成了"或关掉页面后，锁会自动释放。
  - 只看不动（/screen 截图）不需要锁。

## 4. 通用习惯

- 中文用户全部用简体中文，纯文本，不用 Markdown 符号，不用 HTML。
- 收到消息先回一个 👀 表情。
- 慢的活：先发"⏳ 正在……"，做完发一条新消息给结果，再把 ⏳ 那条删掉。
- 要用户亲自做的事（人机验证、登录、密码、验证码、付款）：发 /desk 接管卡片，用户自己点，机器人不代做。
- 不在聊天里回显密钥、token、订阅链接、验证码。
